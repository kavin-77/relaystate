The Core Problem:

When an engineer or tech lead departs, vital institutional memory evaporates. Critical architectural decisions, unmerged branch trade-offs, fragile workarounds, and production risks are scattered across git commits, Slack/Teams discussions, and Jira tickets — and lost forever. Traditional handover documents are hurried, ungrounded, full of hallucinations, and decay instantly.

The RelayState Solution:

RelayState automatically extracts, cross-examines, verifies, and delivers a human-governed handover document where every single claim links to its verbatim source quote. It detects when discussions are superseded by code, redacts secrets prior to storage, and seals transition milestones in an immutable cryptographic audit ledger.

01

Multi-Modal Grounding & Zero-Hallucination Architecture

Grounding Foundation

RelayState rejects black-box summarization. Generative models hallucinate dates, commit hashes, and rationale. Instead, RelayState treats repository activity as a factual evidence corpus, executing a deterministic pipeline:

01 Verbatim Anchor

Every extracted claim stores an immutable source anchor (commit SHA, PR number, or chat timestamp). Citations are validated verbatim against original raw payloads; dropped if ungrounded.

02 Temporal Precedence

Resolves cross-modal contradictions chronologically. If a chat consensus on Oct 12 agrees on Redis, but commit 7a89b1 on Oct 20 merges Memcached, code overrides chat automatically.

03 Pre-Storage Scrub

Scans and redacts AWS keys (AKIA...), Stripe tokens, emails, and phone numbers before data ever touches SQLite or LLM prompts. Sensitive streams are excluded with justifications.

03

Cryptographic Ledger & Tamper-Evident Audit Chain

Data Trust & Compliance

Corporate offboarding requires non-repudiation. RelayState logs every ingestion, redaction, approval, and receipt event into a sequential SHA-256 hash-chained ledger: Hash_n = SHA-256(Seq || Timestamp || Action || Actor || PrevHash || Diff). Evaluators can interactively break the chain using Simulate Tamper, observe the verification engine locate the exact corrupted block, and execute Restore to return to cryptographic validity.

Three Major Pillars Committed for Round 3

Substantial Innovations

1. Temporal Contradiction Engine (Embedding-Based Cross-Examination)

Objective: Expand beyond deterministic keyword rules to detect subtle, distributed contradictions across time and multi-modal sources using dense semantic embeddings.

  • Semantic Claim Clustering: Generates vector embeddings for every proposition across git commit diffs, PR comments, Slack/Teams chats, and Jira issue descriptions.
  • Cross-Examination Pass: Evaluates opposing assertions (e.g. an issue marked "Resolved: Fixed race condition" contradicted 3 days later in chat: "Queue still dropping events under peak load").
  • Confidence-Scored Conflict Resolution: Surfaces an interactive contradiction card displaying both source quotes, chronological delta, and confidence score, prompting reviewers to confirm the prevailing reality.

2. Role-Based Sensitivity Views (Developer vs. Managerial Perspectives)

Objective: Provide tailored handover lenses based on organizational roles and data sensitivity clearance, eliminating cognitive overload while safeguarding proprietary data.

  • Developer Succession Lens: Focuses on deep technical architecture: database schema oddities, custom undocumented workarounds, technical debt, and code-level blockers with direct commit diff links.
  • Managerial Lens: Highlights operational continuity: external vendor point-of-contacts, contractual obligations, SLA risks, and module bus-factor concentration (flagging areas with >80% solo ownership).
  • Per-Claim Sensitivity Tags: Claims carry sensitivity attributes (INTERNAL_ENG, LEADERSHIP, PUBLIC_API) ensuring engineers and leaders view appropriate operational scopes.

3. Interactive Day-1 Navigator (Actionable Onboarding Plan & Audit Tracking)

Objective: Transform the static successor document into an interactive, auditable Day-1 onboarding flight plan that accelerates time-to-productivity for new joiners.

  • Interactive Task Checklist: Synthesizes immediate onboarding tasks (e.g. "Rotate PayNova webhook token", "Review billing retry mechanism", "Meet with Sarah regarding SMS gateway").
  • Contextual Evidence Pinning: Each task links directly to the specific claim and underlying code/chat citation, enabling instant orientation without asking senior engineers.
  • Cryptographic Completion Milestones: Successor completion checkboxes and sign-offs trigger verifiable entries into the SHA-256 audit ledger, creating a formal audit trail of transferred duty.
